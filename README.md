# GHUBBatteryTray

Logicool / Logitech のワイヤレスデバイスのバッテリー残量を、Windows のタスクトレイに表示する常駐アプリです。デバイスと直接通信するため、Logicool G HUB は不要です。残量が設定値を下回ったときの通知と、Webhook (Discord / Slack など) への送信に対応しています。

## 主な機能

- 残量の取得元 (上から優先)
  1. デバイスとの直接通信 (HID++)。G HUB 不要
  2. G HUB のローカル API (`ws://localhost:9010`)
  3. G HUB の `settings.db`
- 残量・充電の開始と終了・接続と切断・スリープからの復帰を、デバイスからの通知で 1 秒以内に反映 (60 秒ごとの取得も併用)
- タスクトレイアイコンの色で残量を表示 (初期値: 緑 50% 超 / 橙 21〜50% / 赤 20% 以下 / 青 充電中 / 灰 未接続)。色と区切りは変更可能
- 複数のデバイスを、それぞれ別のアイコンで表示
- 残量・残り時間・放電量 (mW) を、設定画面・右クリックメニュー・ツールチップに表示
- 充電中は、電池に入っている電力 (推定 mW) と満充電までの時間も表示 (充電中に残量が 2 回上がった時点から。残量の上がり方 × 推定容量で計算)
- デバイスの詳細
  - 残量の推移 (実測は実線、使い方に沿った予測は点線)
  - 時間帯ごとの減り方、1 日の消費
  - バッテリーの健康状態 (推定容量・満充電での使用時間・充電サイクル・劣化と買い替えの目安)
- デバイスごとの残量低下の通知。通知文に置換文字 (デバイス名・残量など) を使用可能
- 充電完了の通知
- フルスクリーン中の通知を保留し、終了後にまとめて表示 (オフにできる)
- Webhook (Discord / Slack / 汎用 JSON) への送信
- 7 言語対応 (日本語 / English (US・UK) / Deutsch / Français / 한국어 / 简体中文)。初期値は Windows の表示言語
- テーマ: システム (Windows の設定に従う) / ライト / ダーク
- Windows 起動時に自動で開始
- アプリ内アップデート (確認・ダウンロード・入れ替え・再起動)。自動確認はオフにできる
- 起動時に exe のハッシュ値を GitHub のリリースと照合し、一致しない場合は起動しない
- 常駐中のメモリ使用量: 約 2〜3 MB (専用メモリ)
- 設定・ログ・残量の履歴・長期の統計を、ユーザーのローカルアプリデータに保存

## 動作環境

- Windows 10 / 11 (64 ビット)
- Logicool / Logitech のワイヤレスデバイス (LIGHTSPEED / Unifying / Bolt 受信機経由。有線・Bluetooth 接続は未確認)
- G HUB は不要。起動していれば、残り時間・放電量の表示と、直接通信で読めないデバイスの補完に使用
- .NET などのランタイムは不要

> [!NOTE]
> 直接通信で残量を読めるのは、HID++ 2.0 のバッテリー機能 (Unified Battery / Battery Status / Battery Voltage) に対応したデバイスです。
> 直接通信と G HUB で同じデバイスかどうかは、デバイス固有の番号 (unitId)、製品 ID、名前の順で判断します。
> 以前のバージョンで直接通信と G HUB の名前に分かれて記録されていた統計・履歴・放電の記録・通知ルールは、常駐の起動時に G HUB 側の名前へ自動でまとめます。同じ時間の二重の記録は 1 つにし、古い統計ファイルは `.bin.merged` として残します。
> 電圧から残量を推定するデバイス (Battery Voltage。G703 など) は充電中に高めの値になるため、G HUB が起動していれば G HUB の残量と充電状態を使い、電圧の推定だけでは充電完了の通知を出しません。
> 無線デバイスはスリープすると応答しないため、その間は前回の値を「スリープ中」と表示するか、受信機の通知に従って「未接続」と表示します。
> 残り時間と放電量は G HUB の推定値で、G HUB の起動中だけ表示されます。
> 充電電力は、電池に入った分の推定値です。USB から取っている電力はこれより少し多くなります。デバイス・G HUB・Windows のいずれからも充電電力を直接読めないため、計算で求めています。

## インストール / 起動方法

### 配布版を使う場合

1. `GHUBBatteryTray.exe` を任意のフォルダーに置きます。
2. ダブルクリックで起動します。インストールは不要です。

旧バージョン (C# 版) は終了してから起動します。設定ファイルはそのまま引き継がれます。

### Visual Studio からビルドする場合

必要なもの:

- Visual Studio 2022 以降 (「C++ によるデスクトップ開発」ワークロード)。Visual Studio 2026 で確認済み
- Rust (https://rustup.rs)

1. `GHUBBatteryTray.sln` を Visual Studio で開きます。
2. 構成を `Release` / `x64` にします。
3. `ビルド` → `ソリューションのビルド` を実行します。
4. `bin\Release\GHUBBatteryTray.exe` が作成されます。

`F5` / `Ctrl + F5` で起動もできます。ビルド・リビルド・クリーンは内部で `cargo` を呼び出します。

> [!NOTE]
> フォルダーのパスが 60 文字を超える場合は、Windows の 260 文字制限によるリンクエラーを避けるため、中間ファイルを `%LOCALAPPDATA%\GHUBBatteryTray-build\` に置きます。このフォルダーは削除しても問題ありません。

### コマンドラインからビルドする場合

```powershell
cargo build --release
```

`target\release\ghub_battery_tray.exe` が作成されます。

> [!WARNING]
> コマンドラインでビルドした exe には、ソースのパス (`C:\Users\<ユーザー名>\.cargo\...` など) が埋め込まれ、Windows のユーザー名が含まれます。配布用の exe は `GHUBBatteryTray.sln` (Visual Studio / MSBuild) でビルドします。こちらはパスを `~` などに置き換えるため、ユーザー名は含まれません。

## 使い方

### 1. 起動する

`GHUBBatteryTray.exe` を起動すると、タスクトレイに残量のアイコンが表示されます。残量はデバイスからの通知と 60 秒ごとの取得で更新されます。

### 2. タスクトレイに表示するデバイスを選ぶ

1. タスクトレイアイコンを右クリックします。
2. デバイス一覧から、表示するデバイスを選びます。
   - 選ぶたびに表示 / 非表示が切り替わります。複数選ぶと、デバイスごとに別のアイコンが表示されます。
   - 設定画面の歯車 → `アイコン表示`、またはカード右上のアイコン (表示中は残量の色、非表示はグレー) をクリックしても切り替えられます。
3. 何も表示しない場合は `表示しない` を選びます。

選んだデバイスが見つからない場合や、どのデバイスも選んでいない場合は、灰色の `--` が表示されます。

### 3. 設定画面を開く

次のどちらかで開きます。

- タスクトレイアイコンを左クリック
- タスクトレイアイコンを右クリック → `設定を開く...`

設定画面には、デバイスごとの残量・残り時間・放電量が表示されます。表示は常駐が取得するたびに更新されます (常駐が動いていない場合は 60 秒ごとに読み直し)。右上の歯車で、言語・アイコン表示・通知・Webhook・起動・更新・残量の色の設定を開きます (`← 戻る` で戻ります)。カードをクリックすると、そのデバイスの通知設定の編集と、カードの下の詳細の表示に切り替わります (もう一度クリックで閉じます)。

詳細の表示内容:

| 項目 | 内容 |
| --- | --- |
| 残量の推移 | 実測の減り方 (実線) と、時間帯ごとの使い方に沿った予測 (点線) |
| 推定容量 | 直近 30 日に使ったエネルギー (放電量 × 時間) ÷ 減った残量 (Wh) |
| 満充電での使用時間 | 直近 30 日の記録から求めた、使用中に 100% から 0% までもつ時間 |
| 容量 (記録開始時比) | 記録開始時と比べた容量 |
| 1 回の充電で | 直近 30 日の 1 日あたりの消費から求めた、満充電から 0% までの日数 |
| 充電時間 | 直近 30 日の記録から求めた、0% から 100% までの充電時間 |
| 充電サイクル | 記録開始以降に減った残量の合計 ÷ 100 |
| 劣化の目安 | 容量が 80% になる時期 |
| 買い替えの目安 | 容量が 70% になる時期 |
| 時間帯ごとの減り方 | 直近 30 日の、時刻ごとの 1 時間あたりの平均の減り (使っていない時間を含む) |
| 1 日の消費 | 直近 30 日の、1 日に減った残量の合計 |

> [!NOTE]
> 値は、1 時間ごとに記録した長期の統計から計算します。
> - **推定容量**: 放電量 (G HUB の起動中に取得) が分かっていた時間に使ったエネルギーを、その間に減った残量で割ります。使う時間の長さには左右されません。放電量が分からない場合は、使用中の減り方から求めた使用時間で比べます。
> - **容量・劣化の目安**: 記録を 14 日ごとに区切って容量を求め、最初の区切りと比べます (28 日以上の記録で表示)。3 区切り (42 日) 以上の記録があれば、減った残量で重み付けした回帰直線から、容量が 80% / 70% になる時期を求めます。それまでは、一般的なリチウムイオン電池の寿命 (約 400 回で容量 80%、約 600 回で 70%) と最近の充電ペースから求めます。
> - **残量の予測**: 時間帯ごとに「使っている割合 × 使用中の減り + 使っていない割合 × 使っていない間の減り」を求め、現在の残量から順に引いて 0% になる時刻を出します。現在の時間帯の残りは、現在の減り方で計算します。
>
> マウスは使わない間スリープして電池をほとんど消費しないため、使い方によって実際の容量とは差が出ます。いずれも推定値です。

### 4. 通知を追加する

1. 設定画面の上部で、対象のデバイスのカードをクリックします。
2. `＋ 通知追加` をクリックします。
3. 追加された行を編集します。
   - `有効`: 通知を有効にする場合にチェック
   - `残量 (%) 以下`: 通知を出す残量のしきい値
   - `アイコン`: 通知のアイコン (なし / 情報 / 警告 / エラー)
   - `通知内容`: 通知のメッセージ
4. `保存` をクリックします。

残量がしきい値以下になると通知が表示されます。同じしきい値の通知は 1 回だけで、残量がしきい値より上に戻るとリセットされます。充電中は残量低下の通知を出しません。

充電完了の通知は、カードの詳細の `バッテリーの健康状態` の右端にあるベルのアイコンで切り替えます (オンは青、オフはグレーに斜線)。

フルスクリーン表示 (ゲーム・動画など) の間は Windows の通知を保留し、終了後にまとめて表示します (2 件以上は 1 つにまとめます)。歯車 → `通知` の `フルスクリーン中は通知を保留` でオフにできます。Webhook は保留せずに送信します。

### 5. 通知を削除する

対象の行の `削除` をクリックし、`保存` をクリックします。

### 6. Webhook に通知を送る

1. 設定画面の歯車 → `Webhook 通知` を開きます。
2. `Webhook に送信する` にチェックを入れます。
3. `URL` を入力し、`形式` を選びます。
   - Discord: チャンネル設定 → 連携サービス → ウェブフック で URL を作成
   - Slack: Incoming Webhooks アプリで URL を作成
   - 汎用 JSON: `{"title", "message", "device", "battery", "event"}` を POST (Home Assistant / n8n など)
4. `テスト送信` で届くことを確認し、`保存` をクリックします。

右クリックメニューの `Webhook 通知` でも有効 / 無効を切り替えられます。

> [!WARNING]
> Webhook の URL には認証用のトークンが含まれます。公開しないでください。

### 7. 言語を切り替える

歯車 → `言語` で選びます。選んだ時点で設定画面・タスクトレイ・通知に反映されます。`Windows の設定` は Windows の表示言語に従います (対応していない言語の場合は英語)。

### 8. テーマを切り替える

- 設定画面右上の `テーマ` ボタンを押すたびに、システム → ライト → ダーク の順に切り替わります。
- 右クリックメニューの `テーマ` からも選べます。

`システム` は Windows の「アプリ モード」(ライト / ダーク) に従います。

### 9. 残量を読み直す

右クリックメニューの `残量を今すぐ再取得`、または設定画面の `残量を再取得` で、すぐに読み直します。

### 10. Windows 起動時に自動で開始する

歯車 → `起動` の `Windows 起動時に開始` をオンにします。右クリックメニューの `Windows 起動時に開始` でも切り替えられます。

### 11. 残量の色を変える

1. 設定画面の歯車を押します。
2. `残量の色` で、段階ごとの上限 (%) と色を設定します。上から順に「この % 以下ならこの色」で、最後の段階は 100% までです。
   - 色見本をクリックして色を選びます。
   - `＋ 段階を追加` で段階を増やします (最大 8 段階)。
   - `充電中` と `未接続` の色も変更できます。
   - `初期値に戻す` で初期の色 (緑 / 橙 / 赤 / 青 / 灰) に戻ります。
3. `保存` をクリックします。

設定画面の色はすぐに、タスクトレイのアイコンは保存時に変わります。

### 12. 更新する

新しいバージョンが GitHub で公開されると、Windows の通知で知らせます (起動時と 1 日 1 回確認)。

1. 通知をクリックするか、設定画面の歯車を押します。
2. `更新` に新しいバージョンが表示されたら、`更新` ボタンを押します。
3. ダウンロードと入れ替えのあと、アプリが自動で再起動します。設定と記録は引き継がれます。

- `今すぐ確認` ですぐに確認できます。
- `更新を自動で確認する` をオフにすると、自動で確認しません (`保存` で反映)。
- 入れ替えは `更新` ボタンを押したときだけ行います。
- 書き込みできない場所 (`C:\Program Files` など) に置いた exe は更新できません。表示される `リリースページを開く` から手動でダウンロードします。
- ダウンロードした exe は、GitHub がリリース時に付けるハッシュ値 (SHA-256) と照合してから入れ替えます。

> [!NOTE]
> 更新の確認と起動時の確認のため、GitHub (`api.github.com` / `github.com`) に接続します。送るのはリリース情報の取得要求だけで、個人情報や設定は送りません。

### 起動時の確認 (改ざん・破損の検出)

起動のたびに exe の SHA-256 を計算し、GitHub の同じバージョンのリリース (例: v2.1.0 なら `v2.1` / `v2.1.0` タグ) の添付ファイルのハッシュ値と比べます。

| 結果 | 動作 |
| --- | --- |
| 一致 | そのまま起動 |
| 不一致 | 「起動を中止しました」と表示して起動しない (`はい` でリリースページを開く) |
| 確認できない (オフライン・このバージョンのリリースがないなど) | ログに警告を残して起動。以前に一致を確認した exe は、オフラインでも確認済みとして扱う |

> [!WARNING]
> この確認で検出できるのは、ダウンロード中の破損と、exe だけが差し替えられた場合です。GitHub のアカウント自体が乗っ取られた場合などは検出できません。

### 13. 終了する

タスクトレイアイコンを右クリック → `終了` を選びます。

## 通知文で使える置換文字

通知内容の入力欄で `{` を入力するか `Tab` キーを押すと、置換文字の候補が表示されます。

- 入力中の文字に近い順 (前方一致 → 部分一致 → 説明に含む → 綴りが近い) で並び、同じ順位は名前順です。未入力のときは名前順です。
- 候補には `{名前}`・意味・例 (選んでいるデバイスの現在の値) が表示されます。
- `Tab` / `↓` で下へ、`Shift + Tab` / `↑` で上へ移動し、`Enter` かクリックで決定、`Esc` で閉じます。
- 入力欄にカーソルを合わせると、現在の値で置き換えたプレビューが表示されます。

| 置換文字 | 内容 | 例 |
| --- | --- | --- |
| `{name}` | デバイス名 | PRO 2 LIGHTSPEED |
| `{battery}` | 通知のしきい値 (%) | 20 |
| `{now}` | 現在の残量 (%) | 18 |
| `{bar}` | 残量のバー表示 | ■■□□□□□□□□ |
| `{remain}` | 残り時間 (G HUB 起動時) | 約3時間 |
| `{empty_at}` | 0% になる予測時刻 | 21:40ごろ / 明日 6:10ごろ |
| `{rate}` | 現在の消費ペース | -5.3%/時 |
| `{pace}` | 平均との比較 (消費ペース) | 平均より速い / 平均的 / 平均より遅い |
| `{power}` | 放電量 | 14.7 mW |
| `{source}` | 取得元 | 直接通信 |
| `{time}` | 通知した時刻 | 18:05 |
| `{since}` | 最後に充電してからの時間 | 9時間 |
| `{streak}` | 充電せずに使い続けた最長記録 | 3日 |
| `{health}` | 容量 (記録開始時比) | 97% |
| `{cycles}` | 充電サイクル | 7.9回 |
| `{replace}` | 買い替えの目安 | 2027年6月ごろ |
| `{rn}` | 改行 | |

値が分からない場合 (G HUB が起動していない、記録が足りないなど) は `不明` になります。例の書き方は表示言語に合わせて変わります。

例:

```text
{name} の残量が {now}% {bar}{rn}このままだと {empty_at} に切れます ({rate}・{pace})
```

## 設定ファイルとログ

保存先:

```text
%LOCALAPPDATA%\GHUBBatteryTray
```

主なファイル:

- `settings.json`: 表示するデバイス、通知設定、Webhook、テーマ、言語、残量の色 (旧バージョンと共通)
- `history.csv`: グラフ用の残量の履歴 (7 日分)
- `health.csv`: 放電の記録 (統計を取り始める前の充電サイクルの計算に使用)
- `stats\<デバイス名>.bin`: 1 時間ごとの長期の統計 (健康状態・使い方の計算に使用。削除すると統計を最初から取り直す)
- `aliases.json`: 直接通信で見つけたデバイス名と、設定で使う名前の対応表
- `update.json`: 更新の確認結果 (最後に確認した日時・最新のバージョン・確認済みの exe のハッシュ値)
- `logs\GHUBBatteryTray.log`: ログ (1 MB を超えると `GHUBBatteryTray.log.old` に移す)。設定画面の左下のフォルダーアイコンから開ける

### 統計ファイルの形式

`stats\<デバイス名>.bin` は、容量と読み書きの量を抑えるための固定長のバイナリーファイルです。

- 先頭 8 バイト: `GHBS` + 形式の版 (u16) + 予備 (u16)
- 以降、1 時間 1 レコード (20 バイト、リトルエンディアン)

| 位置 | 型 | 内容 |
| --- | --- | --- |
| 0 | u32 | 時 (unix 秒 ÷ 3600、UTC) |
| 4 | u16 | 使用中 (接続・放電中で、15 分以内の間隔で読めた区間) の秒数 |
| 6 | u16 | 使用中に減った残量 (1/1000 %) |
| 8 | u16 | 読めなかった間 (スリープ・PC 停止など) に減った残量 (1/1000 %) |
| 10 | u16 | 充電中の秒数 |
| 12 | u16 | 充電で増えた残量 (1/1000 %) |
| 14 | u16 | 放電量の平均 (1/100 mW) |
| 16 | u16 | 放電量が分かっていた秒数 |
| 18 | u16 | 放電量が分かっていた間に減った残量 (1/1000 %) |

- 書き込みは「追記」か「最後のレコードの上書き」のみで、5 分に 1 回 (と終了時) に 20 バイト。
- 1 年で約 171 KB / デバイス。一括で読み込み、数ミリ秒で終わる。
- 残量は 1/1000 % 単位で積み上げるため、整数 % の読み取りでも長期の合計はずれない。
- 書き込み中の異常終了で残った半端なレコードは、次の読み書きで捨てる。
- 統計ファイルがないデバイスは、初回に `history.csv` (直近 7 日) から作成する。

### ログ

記録する内容: 起動・終了、起動時の環境と設定の概要、デバイスの検出、取得元の切り替え、充電の開始 / 終了、スリープ、通知、Webhook の送信結果、設定の保存、統計の概要、各処理の失敗とその理由、異常終了の場所。同じ失敗が続く場合は、内容が変わったときと回復したときだけ記録します。Webhook の URL は記録しません。

## トラブルシューティング

### タスクトレイに `--` と表示される

- 表示するデバイスを選んでいない: 右クリックメニューで選びます。
- デバイスの電源が切れている、または受信機が外れている。
- 起動時からデバイスがスリープしている: マウスを動かすと、通知を受けてすぐに表示されます。

### 設定画面にデバイスが表示されない

- 受信機が PC に挿さっているか、デバイスの電源が入っているかを確認します。
- デバイスがバッテリー残量の取得に対応しているかを確認します。
- 設定画面の `残量を再取得` を押します。

### 残り時間・放電量が表示されない

- G HUB の推定値のため、G HUB の起動中だけ表示されます。

### 通知が表示されない

- 通知設定の `有効` にチェックが入っているか。
- `残量 (%) 以下` の値が現在の残量以上か。
- 充電中ではないか (充電中は残量低下の通知を出しません)。
- フルスクリーン中ではないか (終了後に表示されます。歯車 → `通知` でオフにできます)。
- Windows の設定で通知が無効になっていないか。

### Webhook が届かない

- 歯車 → `Webhook 通知` の `テスト送信` を押し、結果を確認します。
- URL と `形式` (Discord / Slack / 汎用 JSON) が送信先に合っているかを確認します。

### リリースの手順

アプリは GitHub のリリースを見て、更新の判断と起動時の確認を行います。

1. `Cargo.toml` の `version` を上げます (例: `3.1.0` → `3.1.1`)。**タグと同じバージョンにします** (`v3.1` と `3.1.0` は同じ扱い)。
2. `GHUBBatteryTray.sln` を `Release` でビルドします (パスにユーザー名を含まない配布用 exe になります)。
3. GitHub でリリースを作成します。
   - タグ: `v` + バージョン (例: `v3.1.1`)
   - 添付: `bin\Release\GHUBBatteryTray.exe` を 1 つ (ファイル名は `GHUBBatteryTray.exe`)
   - Draft / Pre-release にしない (最新リリースとして扱われないため)
   - ハッシュ値は GitHub がアップロード時に自動で付けるため、記載は不要
4. **リリース後に exe を作り直さないこと。** 添付した exe と配布する exe (BOOTH など) が 1 バイトでも違うと、起動時の確認で一致せず起動しません。作り直した場合は、リリースの添付ファイルも差し替えます。

> [!NOTE]
> 開発中の Release ビルドは、同じバージョンのリリースとハッシュ値が一致しないため起動しません (Debug ビルドは確認しません)。Release ビルドで試す場合は、環境変数 `GHBT_SKIP_INTEGRITY=1` を付けて起動するか、未リリースのバージョン番号にします。
