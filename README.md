# GHUBBatteryTray

GHUBBatteryTray は、Logicool / Logitech のワイヤレスデバイスのバッテリー残量を Windows のタスクトレイに表示する常駐アプリです。デバイスと直接通信して残量を読み取るため、Logicool G HUB がなくても動作します。指定したバッテリー残量を下回ったときに、デバイスごとの通知や Webhook (Discord / Slack など) への通知も行えます。

## 主な機能

- バッテリー残量を次の順で取得 (上から優先)
  1. デバイスとの直接通信 (HID++) … G HUB 不要
  2. G HUB のローカル API (`ws://localhost:9010`)
  3. G HUB の `settings.db`
- タスクトレイアイコンに残量を色付きで表示 (既定: 緑 50% 超 / 橙 21〜50% / 赤 20% 以下 / 青 充電中 / 灰 未接続)。残量ごとの色は設定で変更可能
- 複数のデバイスをそれぞれ別のアイコンで同時に表示 (マウスとヘッドセットなど)
- 残量・残り時間・放電量 (消費電力 mW) を設定画面・右クリックメニュー・アイコンのツールチップに表示
- デバイスのカードをクリックすると詳細が開き、減り具合のグラフ (実績は実線、使い方に沿った予測は点線)、時間帯ごとの減り方と 1 日の消費のグラフ、バッテリーの健康状態 (推定容量・充電サイクル・劣化や買い替えの目安) を表示
- デバイスごとにバッテリー残量の通知設定を設定
- 通知文言にデバイス名や残量を差し込めるテンプレート機能
- 充電完了の通知
- ゲームや動画をフルスクリーンで表示している間は通知を待ち、終わったらまとめて表示 (設定でオフ可)
- 通知を Webhook (Discord / Slack / 汎用 JSON) にも送信。有効・無効は設定画面と右クリックメニューで切り替え
- ライト / ダーク / システム (Windows の設定に合わせる) のテーマ切り替え。初期設定はシステム
- Windows 起動時に自動で開始
- アップデート: 新しいバージョンが出たら通知し、設定画面のボタン 1 つでダウンロード・入れ替え・再起動まで完了 (自動確認は設定でオフ可)
- 起動時に exe が GitHub で公開しているものと同じか (ハッシュ値) を確認し、一致しなければ起動しない
- 常駐中のメモリ使用量は約 2〜3 MB
- 設定・ログ (INFO / WARN / ERROR、必要に応じて DEBUG)・残量の履歴をユーザーのローカルアプリデータに保存

## 動作環境

- Windows 10 / 11 (64 ビット)
- Logicool / Logitech のワイヤレスデバイス (LIGHTSPEED / Unifying / Bolt レシーバー経由。有線・Bluetooth 接続にも対応する作りですが未確認です)
- Logicool G HUB は不要です (インストールされている場合は、残り時間・放電量の表示や、直接通信で読めないデバイスの補完に使います)
- .NET などのランタイムは不要です

> [!NOTE]
> 直接通信で残量を読めるのは、HID++ 2.0 のバッテリー機能 (Unified Battery / Battery Status / Battery Voltage) に対応したデバイスです。
> 無線デバイスは省電力でスリープすると応答しなくなるため、その間は前回の値を「スリープ中」として表示します。
> 残り時間と放電量は G HUB が推定した値で、G HUB が起動しているときだけ表示されます。

## インストール / 起動方法

### 配布版を使う場合

1. `GHUBBatteryTray.exe` を好きなフォルダーに置きます。
2. ダブルクリックで起動します。インストールは不要です。

旧バージョン (C# 版) を使っていた場合は、旧バージョンを終了してから起動してください。設定ファイルはそのまま引き継がれます。

### Visual Studio からビルドする場合

必要なもの:

- Visual Studio 2022 以降 (「C++ によるデスクトップ開発」ワークロード)。Visual Studio 2026 で確認済み
- Rust (https://rustup.rs からインストール)

1. `GHUBBatteryTray.sln` を Visual Studio で開きます。
2. 構成を `Release` / `x64` にします。
3. `ビルド` → `ソリューションのビルド` を実行します。
4. `bin\Release\GHUBBatteryTray.exe` が作成されます。

`F5` / `Ctrl + F5` でそのまま起動もできます。ビルド・リビルド・クリーンは内部で `cargo` を呼び出します。

> [!NOTE]
> フォルダーのパスが長い場合 (60 文字超) は、Windows の 260 文字制限でリンクに失敗しないよう、ビルドの中間ファイルを `%LOCALAPPDATA%\GHUBBatteryTray-build\` に自動で置きます。不要になったら、このフォルダーは削除してかまいません。

### コマンドラインからビルドする場合

```powershell
cargo build --release
```

ビルド後、生成された `target\release\ghub_battery_tray.exe` を実行してください。

> [!WARNING]
> コマンドラインでビルドした exe には、エラー表示用にソースのパス (`C:\Users\<ユーザー名>\.cargo\...` など) が埋め込まれ、Windows のユーザー名が含まれます。配布用の exe は `GHUBBatteryTray.sln` (Visual Studio / MSBuild) でビルドしてください。こちらはパスを `~` などに置き換えるので、ユーザー名は含まれません。

## 使い方

### 1. アプリを起動する

`GHUBBatteryTray.exe` を起動すると、タスクトレイに残量のアイコンが表示されます。アプリは 60 秒ごとに残量を読み取り、アイコンを更新します。

### 2. タスクトレイに表示するデバイスを選ぶ

1. タスクトレイアイコンを右クリックします。
2. メニューに表示されたデバイス一覧から、タスクトレイに残量を表示したいデバイスを選択します。
   - 選ぶたびに表示 / 非表示が切り替わります。複数選ぶと、デバイスごとに別のアイコンが表示されます。
   - 設定画面右上の歯車 → `アイコン表示` や、デバイスごとの `アイコン表示` チェックでも切り替えられます。
3. 何も表示しない場合は、`表示しない` を選びます。

選択したデバイスが見つからない場合や、どのデバイスも選んでいない場合、タスクトレイには灰色の `--` が表示されます。

### 3. 設定画面を開く

設定画面は、次のどちらかの操作で開けます。

- タスクトレイアイコンを左クリックする
- タスクトレイアイコンを右クリックし、`設定を開く...` を選択する

設定画面には、デバイスごとの残量・残り時間・放電量が表示されます。右上の歯車で、アイコン表示・通知・Webhook・起動・アップデート・残量の色の設定を開きます (`← 戻る` で元の画面に戻ります)。カードをクリックすると、そのデバイスの通知設定を編集できるようになり、カードの下に詳細が開きます (もう一度クリックで閉じます)。

詳細には次の内容が表示されます。

| 項目 | 内容 |
| --- | --- |
| 残量の推移 | 実際の減り方 (実線) と、時間帯ごとの使い方に沿った予測 (点線) |
| 推定容量 | 直近 30 日に使ったエネルギー (放電量 × 時間) ÷ 減った残量 から求めた容量 (Wh) |
| 満充電での使用時間 | 直近 30 日の記録から求めた、使用中に 100% から 0% までもつ時間 |
| 容量 (記録開始時比) | 記録を始めた頃と比べた容量 |
| 1 回の充電で | 直近 30 日の 1 日あたりの消費から求めた、満充電から 0% までの日数 |
| 充電時間 | 直近 30 日の記録から求めた、0% から 100% までの充電時間 |
| 充電サイクル | 記録を始めてから減った残量の合計 ÷ 100 |
| 劣化の目安 | 容量が 80% になる時期 |
| 買い替えの目安 | 容量が 70% になる時期 |
| 時間帯ごとの減り方 | 直近 30 日の、時刻ごとの 1 時間あたりの平均の減り (使っていない時間も含む) |
| 1 日の消費 | 直近 30 日の、1 日に減った残量の合計 |

> [!NOTE]
> 値は、1 時間ごとに記録した長期の統計から計算します。
> - **推定容量**: 放電量 (G HUB が起動しているときに取得) が分かっていた時間に使ったエネルギーを、その間に減った残量で割って求めます。使い方 (使う時間の長さ) に左右されません。放電量が分からない場合は、使用中の減り方から求めた使用時間で比べます。
> - **容量・劣化の目安**: 記録を 14 日ごとに区切って容量を求め、最初の区切りと比べます (28 日以上の記録で表示)。3 区切り (42 日) 以上たまると、減った残量の量で重み付けした回帰直線から、容量が 80% / 70% になる時期を求めます。それまでは、一般的なリチウムイオン電池の寿命 (約 400 回で容量 80%、約 600 回で 70%) と最近の充電ペースから目安を出します。
> - **残量の予測**: 時間帯ごとに「使っている割合 × 使用中の減り方 + 使っていない割合 × 使っていない間の減り方」を求め、今の残量から順に引いて 0% になる時刻を出します。今の時間帯の残りは、今の減り方で進めます。
> マウスは使わない間スリープして電池をほとんど使わないため、使い方によって実際の容量とはずれます。あくまで目安としてご覧ください。

### 4. 通知を追加する

1. 設定画面の上部で、設定したいデバイスのカードをクリックします。
2. `＋ 通知追加` をクリックします。
3. 一覧に追加された行を編集します。
   - `有効`: 通知を有効にする場合はチェックします。
   - `残量 (%) 以下`: 通知を出すバッテリー残量のしきい値を入力します。
   - `アイコン`: 通知に表示するアイコン (なし / 情報 / 警告 / エラー) を選びます。
   - `通知内容`: 表示する通知メッセージを入力します。
4. `保存` をクリックします。

バッテリー残量が設定したしきい値以下になると、通知が表示されます。同じしきい値の通知は連続して何度も出ないようになっており、残量がしきい値より上に戻ると通知状態がリセットされます。充電中は残量低下の通知を出しません。

充電完了の通知は、設定画面の `充電完了通知` で有効 / 無効を切り替えられます。

ゲームや動画などがフルスクリーンで表示されている間は、Windows の通知を出さずにためておき、フルスクリーンが終わったらまとめて表示します (2 件以上は 1 つの通知にまとめます)。設定画面右上の歯車 → `通知` の `フルスクリーン中は通知を保留` でオフにできます。Webhook はフルスクリーン中も待たずにすぐ送ります。

### 5. 通知を削除する

設定画面で削除したい行の `削除` をクリックし、`保存` をクリックします。

### 6. Webhook に通知を送る

1. 設定画面右上の歯車を押し、`Webhook 通知` を表示します。
2. `Webhook に送信する` にチェックを入れます。
3. `URL` に Webhook の URL を入力し、`形式` を選びます。
   - Discord: チャンネル設定 → 連携サービス → ウェブフック で URL を作成できます。
   - Slack: Incoming Webhooks アプリで URL を作成できます。
   - 汎用 JSON: `{"title", "message", "device", "battery", "event"}` を POST します (Home Assistant / n8n など)。
4. `テスト送信` で届くか確認し、`保存` をクリックします。

Webhook の有効 / 無効は、タスクトレイアイコンの右クリックメニュー `Webhook 通知` でも切り替えられます。

> [!WARNING]
> Webhook の URL には認証用のトークンが含まれます。他人に見せたり、公開したりしないでください。

### 7. テーマを切り替える

- 設定画面右上の `テーマ` ボタンを押すたびに、システム → ライト → ダーク の順に切り替わります。
- タスクトレイアイコンの右クリックメニュー `テーマ` からも選べます。

`システム` を選ぶと、Windows の「アプリ モード」(ライト / ダーク) に合わせて自動で切り替わります。

### 8. 残量をすぐに読み直す

右クリックメニューの `残量を今すぐ再取得`、または設定画面の `残量を再取得` で、60 秒を待たずに最新の残量を読み直します。

### 9. Windows 起動時に自動で開始する

設定画面右上の歯車 → `起動` の `Windows 起動時に開始` をオンにします。右クリックメニューの `Windows 起動時に開始` でも切り替えられます。

### 10. 残量の色を変える

1. 設定画面右上の歯車を押します。
2. `残量の色` で、段階ごとの上限 (%) と色を設定します。上から順に「この % 以下ならこの色」で、最後の段階は 100% までです。
   - 色の四角を押すと色を選べます。
   - `＋ 段階を追加` で段階を増やせます (最大 8 段階)。
   - `充電中` と `未接続` の色も変えられます。
   - `デフォルトに戻す` で最初の色 (緑 / 橙 / 赤 / 青 / 灰) に戻ります。
3. `保存` をクリックします。

設定画面の色はすぐに、タスクトレイのアイコンは保存したときに変わります。

### 11. アップデートする

新しいバージョンが GitHub で公開されると、Windows の通知でお知らせします (アプリの起動時と 1 日 1 回確認)。

1. 通知をクリックするか、設定画面右上の歯車を押します。
2. `アップデート` に `vX.Y.Z が出ています` と表示されたら、`更新` を押します。
3. 新しいバージョンのダウンロード・入れ替えのあと、アプリが自動で再起動します。設定や記録はそのまま引き継がれます。

- `今すぐ確認` で、すぐに確認することもできます。
- `更新を自動で確認する` をオフにすると、自動では確認しません (`保存` で反映)。
- 更新は `更新` を押したときだけ行い、勝手に入れ替わることはありません。
- exe を書き込みできない場所 (`C:\Program Files` など) に置いている場合は更新できません。表示される `リリースページを開く` から手動でダウンロードしてください。

- ダウンロードした exe は、GitHub がリリース時に付けるハッシュ値 (SHA-256) と照合してから入れ替えます。

> [!NOTE]
> 更新の確認と起動時の確認のため、GitHub (`api.github.com` / `github.com`) に接続します。送るのはリリース情報の取得要求だけで、個人情報や設定は送りません。

### 起動時の確認 (改ざん・破損の検出)

起動するたびに、exe の SHA-256 を計算し、GitHub の同じバージョンのリリース (例: v2.1.0 なら `v2.1` / `v2.1.0` タグ) の添付ファイルのハッシュ値と比べます。

| 結果 | 動き |
| --- | --- |
| 一致 | そのまま起動します |
| 不一致 | 「起動を中止しました」と表示して起動しません (`はい` でリリースページを開きます) |
| 確認できない (オフライン・このバージョンのリリースが無いなど) | ログに警告を残して起動します。前に一致を確認できた exe なら、オフラインでも確認済みとして扱います |

> [!WARNING]
> この確認で見つけられるのは、ダウンロード中の破損や、exe だけが差し替えられた場合です。GitHub のアカウント自体が乗っ取られた場合などは防げません。

### 12. アプリを終了する

1. タスクトレイアイコンを右クリックします。
2. `終了` を選択します。

## 通知文言で使える置換文字

通知内容の入力欄で `{` を入力するか `Tab` キーを押すと、置換文字の候補が表示されます。

- 入力中の文字に近い順 (前方一致 → 部分一致 → 説明に含む → 綴りが近い)、同じなら名前順に並びます。何も入力していないときは名前順です。
- 候補には `{名前}`・意味・例 (選んでいるデバイスの今の値) が表示されます。
- `Tab` / `↓` で下へ、`Shift + Tab` / `↑` で上へ選び、`Enter` かクリックで決定、`Esc` で閉じます。
- 入力欄にカーソルを乗せると、今の値で置き換えたプレビューが表示されます。

| 置換文字 | 内容 | 例 |
| --- | --- | --- |
| `{name}` | デバイス名 | PRO 2 LIGHTSPEED |
| `{battery}` | 通知のしきい値 (%) | 20 |
| `{now}` | 現在の残量 (%) | 18 |
| `{bar}` | 残量のバー表示 | ■■□□□□□□□□ |
| `{remain}` | 残り時間 (G HUB 起動時) | 約3時間 |
| `{empty_at}` | 0% になる予測時刻 | 21:40ごろ / 明日 6:10ごろ |
| `{rate}` | 現在の消費ペース | -5.3%/時 |
| `{pace}` | 平均との比較 (消費ペース) | 平均より速い / 平均的 / 平均より遅い |
| `{power}` | 放電量 | 14.7 mW |
| `{source}` | 取得元 | 直接通信 |
| `{time}` | 通知した時刻 | 18:05 |
| `{since}` | 最後に充電してからの時間 | 9時間 |
| `{streak}` | 充電せずに使い続けた最長記録 | 3日 |
| `{health}` | 容量 (記録開始時比) | 97% |
| `{cycles}` | 充電サイクル | 7.9回 |
| `{replace}` | 買い替えの目安 | 2027年6月ごろ |
| `{rn}` | 改行 | |

値が分からないとき (G HUB が起動していない、記録がまだ足りないなど) は `不明` になります。

例:

```text
{name} の残量が {now}% {bar}{rn}このままだと {empty_at} に切れます ({rate}・{pace})
```

## 設定ファイルとログ

設定ファイルとログは、次のフォルダーに保存されます。

```text
%LOCALAPPDATA%\GHUBBatteryTray
```

主なファイルは次のとおりです。

- `settings.json`: アイコン表示するデバイス、通知設定、Webhook、テーマ、残量の色の設定 (旧バージョンと共通)
- `history.csv`: グラフ用の残量の履歴 (7 日分)
- `health.csv`: 放電の記録 (統計を取り始める前の充電サイクルの計算に使います)
- `stats\<デバイス名>.bin`: 1 時間ごとの長期の統計 (健康状態・使い方の計算用。削除すると統計を最初からやり直します)
- `aliases.json`: 直接通信で見つけたデバイス名と、設定で使っている名前の対応表
- `update.json`: 更新の確認結果 (最後に確認した日時・最新のバージョン・確認できた exe のハッシュ値)
- `logs\GHUBBatteryTray.log`: アプリのログ (1 MB を超えると `GHUBBatteryTray.log.old` に移して新しく書きます)。設定画面の左下のフォルダーアイコンから開けます

### 統計ファイルの形式

`stats\<デバイス名>.bin` は、データの量と読み書きを小さくするための固定長のバイナリーファイルです。

- 先頭 8 バイト: `GHBS` + 形式の版 (u16) + 予備 (u16)
- 以降、1 時間 1 レコード (20 バイト、リトルエンディアン)

| 位置 | 型 | 内容 |
| --- | --- | --- |
| 0 | u32 | 時 (unix 秒 ÷ 3600、UTC) |
| 4 | u16 | 使用中 (接続・放電中で 15 分以内の間隔で読めた区間) の秒数 |
| 6 | u16 | 使用中に減った残量 (1/1000 %) |
| 8 | u16 | 読めなかった間 (スリープ・PC 停止など) に減った残量 (1/1000 %) |
| 10 | u16 | 充電中の秒数 |
| 12 | u16 | 充電で増えた残量 (1/1000 %) |
| 14 | u16 | 放電量の平均 (1/100 mW) |
| 16 | u16 | 放電量が分かっていた秒数 |
| 18 | u16 | 放電量が分かっていた間に減った残量 (1/1000 %) |

- 書き込みは「追記」か「最後のレコードの上書き」だけで、5 分に 1 回 (と終了時) に 20 バイトです。
- 1 年で約 171 KB / デバイスです。読み込みは一括で数ミリ秒です。
- 残量は 1/1000 % 単位で積み上げるので、整数 % の読み取りでも長期の合計はずれません。
- 途中で落ちて半端なレコードが残っても、次に読み書きするときに捨てます。
- 統計ファイルが無いデバイスは、初回に `history.csv` (直近 7 日) から作ります。

ログは次の形式で、起動・終了、起動時の環境と設定の概要、デバイスの検出、取得元の切り替え、充電の開始 / 終了、スリープ、通知、Webhook の送信結果、設定の保存、各処理の失敗とその理由、異常終了の場所などを記録します。同じ失敗が続く場合は、内容が変わったときと回復したときだけ記録します。Webhook の URL はログに書きません。

```text
2026-10-22 12:46:04.064 +09:00 [INFO] I011 アプリを開始しました (バージョン 2.4.0)
2026-10-22 12:46:04.065 +09:00 [INFO] I001 環境: Windows 11 Pro 26H2 (ビルド 26300.9711) / 表示倍率 100% / exe ... / 設定フォルダー ... / 起動オプション なし
2026-10-22 12:46:04.065 +09:00 [INFO] I002 設定: テーマ System / アイコン表示 1 台 / 通知ルール 3 件 (1 台) / フルスクリーン中の保留 オン / 更新確認 オン / Webhook オフ / Windows 起動時に開始 オン / 詳細ログ オフ
2026-10-22 12:46:05.304 +09:00 [INFO] I005 HID 直接通信で見つかったデバイス: PRO 2 LIGHTSPEED (番号 1, 機能 0x1004)
2026-10-22 12:46:05.728 +09:00 [INFO] I013 デバイスを検出: PRO 2 LIGHTSPEED 24% (取得元: G HUB API)
```

環境変数 `GHBT_DEBUG=1` を付けて起動すると、毎回の取得結果や通知ルールの判定などの詳細 (DEBUG) も記録します。

`settings.json` が壊れていて読み込めない場合は、初期設定で起動し、元の内容を `settings.json.broken` に残します。

## トラブルシューティング

### タスクトレイに `--` と表示される

- タスクトレイ表示対象のデバイスが選択されていない可能性があります。右クリックメニューで選んでください。
- デバイスの電源が切れているか、レシーバーが外れている可能性があります。
- 無線デバイスが一度も応答していない (起動直後からスリープしている) 可能性があります。マウスを動かすなどして起こしてください。

### 設定画面にデバイスが表示されない

- レシーバーが PC に挿さっているか、デバイスの電源が入っているか確認してください。
- 対象デバイスがバッテリー残量情報に対応しているか確認してください。
- 設定画面の `残量を再取得` を押してください。

### 残り時間・放電量が表示されない

- これらは G HUB の推定値です。G HUB が起動しているときだけ表示されます。

### 通知が表示されない

- 通知設定の `有効` にチェックが入っているか確認してください。
- `残量 (%) 以下` の値が現在のバッテリー残量以上になっているか確認してください。
- 充電中は残量低下の通知を出しません。
- フルスクリーン中は通知を待ちます。フルスクリーンを終えると表示されます (歯車 → `通知` でオフにできます)。
- Windows 側で通知が無効化されていないか確認してください。

### Webhook が届かない

- 設定画面右上の歯車 → `Webhook 通知` で `テスト送信` を押し、表示される結果を確認してください。
- URL と `形式` (Discord / Slack / 汎用 JSON) が送信先に合っているか確認してください。

### リリースの手順

アプリは GitHub のリリースを見て、更新の判断と起動時の確認を行います。

1. `Cargo.toml` の `version` を上げます (例: `2.1.0` → `2.2.0`)。**タグと同じバージョンにしてください** (`v2.2` と `2.2.0` は同じ扱い)。
2. `GHUBBatteryTray.sln` を `Release` でビルドします (ユーザー名がパスに含まれない配布用 exe になります)。
3. GitHub でリリースを作成します。
   - タグ: `v` + バージョン (例: `v2.2.0`)
   - 添付: `bin\Release\GHUBBatteryTray.exe` を 1 つ (ファイル名は `GHUBBatteryTray.exe`)
   - Draft / Pre-release にしないこと (最新リリースとして扱われません)
   - ハッシュ値は GitHub がアップロード時に自動で付けるので、自分で書く必要はありません
4. **リリースした後に exe を作り直さないこと。** 添付した exe と配布する exe (BOOTH など) が 1 バイトでも違うと、起動時の確認で「一致しません」となり起動しません。作り直した場合は、リリースの添付ファイルも差し替えてください。

> [!NOTE]
> 開発中に Release ビルドを動かすと、同じバージョンのリリースとハッシュ値が一致せず起動しません。Debug ビルドは確認しません。Release ビルドで試すときは、環境変数 `GHBT_SKIP_INTEGRITY=1` を付けて起動するか、まだリリースしていないバージョン番号にしてください。
